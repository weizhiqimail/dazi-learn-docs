C1-01-AWS-CLF-C02系统学习文档：阅读说明与资料来源

1-这套文档的目标​

这套资料不是一份单纯的 AWS 服务字典，也不是一份“719 道题答案解析”。它的目标是建立一套完整的 AWS 知识体系，使学习过程按照下面的顺序进行：

先理解：
云计算为什么存在
        ↓
AWS 的基础设施长什么样
        ↓
AWS 有哪些技术领域
        ↓
每一种 AWS 服务解决什么问题
        ↓
不同服务如何组合成真实系统
        ↓
面对一个业务需求时如何选择服务
        ↓
再回到 719 道题
        ↓
分析题目为什么这样出
        ↓
分析每个选项为什么对、为什么错
        ↓
统计反复出现的知识点
        ↓
针对高频知识进行强化

最终目标不是：

“看到某个关键词，机械地背一个答案。”

而是：

“理解业务需求以后，即使题目换一种写法，也能够自己推出应该使用什么 AWS 服务。”

2-三套知识来源​

这套文档会同时使用三类信息，但不会把它们混在一起。

2.1-★★★★★-第一来源：AWS-当前官方资料​

凡是涉及：

  • AWS 服务现在是什么
  • 某个产品现在是否存在
  • 当前 CLF-C02 考试范围
  • 当前服务名称
  • AWS 官方架构定义
  • 当前 Support 体系
  • 当前 Region / Availability Zone 信息
  • AWS 官方最佳实践

都会优先以 AWS 当前官方文档为准。

AWS 当前 CLF-C02 官方考试指南明确说明，这项认证考察的是与具体职位无关的 AWS Cloud 整体基础知识；当前考试仍然划分为四个领域。(AWS Documentation)官方入口：

AWS Certified Cloud Practitioner CLF-C02 官方考试指南

CLF-C02 当前考试范围内 AWS 服务

CLF-C02 当前考试范围外 AWS 服务

CLF-C02 Technologies and Concepts

2.2-★★★★★-第二来源：719-道题库​

你提供的 JSON 文件明确记录：

exam:
AWS Certified Cloud Practitioner CLF-C02

total_questions:
719

即这套题库共有 719 道题。题目数据不仅包含：question、options、correct_answer；还包含：vote_distribution、comments、explanation；例如第一题就同时包含题库答案、社区投票比例和大量用户评论。因此这份题库非常适合：发现高频服务、发现高频业务场景、发现容易混淆的选项、发现旧题、发现争议题、统计知识点频率；但需要注意：

题库中的 correct_answer 是题库记录的答案，不自动等于 AWS 官方标准答案。

如果题库答案、社区意见和当前 AWS 官方资料之间存在冲突，后续题目解析统一使用：

【题库答案】
A

【当前 AWS 判断】
B 更合理

【原因】
……

【考试处理】
如果属于历史题，需要同时知道旧知识和当前知识。

而不会为了维护题库答案而强行解释。

2.3-第三来源：通用计算机与软件工程知识​

AWS 建立在大量已有的计算机技术之上。例如：

DNS
HTTP
TCP/IP
CIDR
NAT
Load Balancing
Container
Kubernetes
SQL
NoSQL
Cache
Message Queue
Pub/Sub
Encryption
Public Key
Private Key
CDN
API

这些不是 AWS 发明的。所以如果直接说：

Amazon Route 53 是 DNS 服务。

对于没有系统学习过 DNS 的人来说，仍然没有真正解释清楚。因此文档会先解释：

DNS 是什么
↓
传统系统为什么需要 DNS
↓
AWS 为什么提供 Route 53
↓
Route 53 如何进入 GlobalShop

而不是直接从 AWS 产品名开始背。

3-文档中的事实等级​

为了避免“题库说了，所以一定是真的”，整套资料使用下面几种信息等级。

标记含义
【AWS 当前】经过当前 AWS 官方资料确认
【题库】来自这 719 道题
【历史题】题库涉及，但当前 AWS 范围或产品状态已经变化
【推导】根据架构原理作出的合理推导
【教学示例】为了理解而构造的 GlobalShop 示例，不代表真实公司架构
【争议】题库答案、评论或当前 AWS 资料之间存在明显分歧

4-知识重要度​

以后统一使用：★★★★★ 核心知识、★★★★ 高频重点、★★★ 重要知识、★★ 次重点、★ 低频知识、无星 了解即可；星级不是按照 AWS 服务本身“高级不高级”决定。例如：

Amazon EC2        ★★★★★
Amazon S3         ★★★★★
IAM               ★★★★★
Amazon VPC        ★★★★★
CloudWatch        ★★★★★

AWS Wavelength    ★

并不是说 Wavelength 技术上“不重要”。而是综合考虑：CLF-C02 当前范围、+、719 题出现情况、+、是否经常成为正确答案、+、是否频繁成为干扰选项、+、是不是理解其他知识的基础

5-当前考试范围与题库范围不是一回事​

这一点非常重要。AWS 官方目前明确列出了 CLF-C02 的 In-Scope 和 Out-of-Scope 服务，并说明这些清单是 non-exhaustive（非穷尽）且可能变化。(AWS Documentation)

例如当前官方 In-Scope 中包括：

Amazon EC2
Amazon S3
Amazon RDS
Amazon DynamoDB
Amazon VPC
Amazon CloudFront
Route 53
IAM
GuardDuty
Inspector
CloudWatch
CloudTrail
AWS Config
CloudFormation
Lambda
Fargate
ECS
EKS
...

(AWS Documentation)但当前官方 Out-of-Scope 清单又明确列出了：

AWS Wavelength、AWS CodeDeploy、Amazon WorkDocs、AWS IoT Device Defender、Amazon Personalize、...(AWS Documentation)

而这些范围外服务中的一部分仍然出现在题库里。例如题库评论中明确讨论了 AWS Wavelength。因此整套教材不会简单地：

当前 Out-of-Scope
↓
删除

而会标记：

★ 【题库补充】【CURRENT-OUT-OF-SCOPE】

AWS Wavelength

告诉你：

老题可能出现，需要知道它是干什么的；但当前备考优先级已经明显下降。

7-英文的处理规则​

第一次出现的重要专业词必须给出：英文、英文全称（如果存在缩写）、中文、基本含义；例如：

7.1-★★★★★-HA​

HA
= High Availability
= 高可用性

7.2-★★★★-DR​

DR
= Disaster Recovery
= 灾难恢复 / 灾备

7.3-★★★-CDN​

CDN
= Content Delivery Network
= 内容分发网络

7.4-★★★★★-IAM​

IAM
= Identity and Access Management
= 身份与访问管理

之后再使用：HA、DR、CDN、IAM；就不需要每一次重新展开。

8-GlobalShop-的作用​

整套教材不会每介绍一个 AWS 服务就发明一家新公司。固定使用：

GlobalShop 全球电商平台

作为主案例。例如：

EC2
→ 商品系统服务器

S3
→ 商品图片

RDS / Aurora
→ 订单数据库

DynamoDB
→ 大规模 Key-Value 数据

CloudFront
→ 全球商品图片分发

Route 53
→ shop.example.com DNS

SQS
→ 下单之后的异步任务

IAM
→ 员工、服务和资源权限

CloudWatch
→ CPU、请求量、错误率

CloudTrail
→ 谁修改了 AWS 资源

Budgets
→ 双十一云资源成本预警

于是整套 AWS 最终会形成一个完整系统，而不是几十个孤立产品。

9-学习顺序​

不要一开始背：EC2、S3、RDS、IAM、VPC、CloudTrail、...；推荐采用：

第一阶段
理解 AWS 世界

传统机房
↓
Cloud
↓
Region / AZ
↓
Compute / Storage / Database / Network

第二阶段
学习各个服务

EC2
S3
RDS
...

第三阶段
学习服务之间的关系

EC2 + EBS
EC2 + IAM Role + S3
ALB + EC2 + Auto Scaling
CloudFront + S3
...

第四阶段
真实业务架构

GlobalShop

第五阶段
719题

第六阶段
频率强化

10-本文档不是部署手册​

CLF-C02 是 Foundational Level（基础级）认证。当前官方定义也是验证 AWS Cloud、服务和术语的基础、高层次理解。(Amazon Web Services)所以这套资料重点解决：

What
是什么

Why
为什么

When
什么时候使用

Which
应该选哪个

而不是把大量篇幅花在：AWS Console 点哪个按钮、CLI 参数怎么写、Terraform 怎么配置、CloudFormation YAML 每个字段、Kubernetes Manifest 怎么写；这些属于后续 Associate / Professional 或实际工程实践层面的内容。
